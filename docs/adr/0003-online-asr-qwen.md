# 转写环节切换为在线 Qwen3-ASR，取消 LLM 断句重组步骤

转写环节由本地 faster-whisper（large-v3 + stable-ts + GPU）切换为阿里云百炼在线服务 `qwen-audio-3.0-asr-flash-filetrans`。依据是地图 #20 的三语种实测（`out-asr-test/REPORT.md`）：在线模型原生整句率 100%（本地 whisper 原生分段仅 11–24%），句级时间戳与 stable-ts 重锁边界的中位偏差 ≤0.5s，识别准确率与本地链文本相似度 91–99%，3 小时音频云端约 6.5 分钟、¥2.4，且不依赖本机 GPU。原步骤 2（LLM 断句重组，约 10 分钟）因此取消。

## 已考虑的选项

- **维持本地链**：免费、离线可用，但需 GPU 与 3GB 模型，且必须付出 LLM 重组步骤来修复碎句分段。降级为回退路径，不再默认。
- **火山引擎豆包语音识别大模型（Seed-ASR）**：同为实测候选，断句/准确率与 Qwen 持平，但速度全面慢一个量级（10 分钟音频 77–91s vs 首轮轮询即返回），且日语必须显式传 `audio.language`（自动检测会输出汉字音译/罗马字）。落选。
- **Deepgram / AssemblyAI 等海外服务**：调研（#22）显示能力合格但需外币付费，且对中文口语的支持档位弱于国内厂商。未进入实测。
- **保留 LLM 重组做二次打磨**：实测整句率已 100%，再跑一轮 LLM 只剩拆分超长条一件事，而用响应自带的词级时间戳即可纯代码完成，不值得 10 分钟。否决。

## 后果

- 需要 `DASHSCOPE_API_KEY`；识别按时长计费（¥0.79/小时，一条 10 分钟视频约 ¥0.13）。
- API 要求音频走公网 URL：本方案用 cloudflared 临时隧道中转本机 HTTP 服务（`--protocol http2`，与 TUN 代理共存；异常时可回退手工上传 OSS）。
- 分段在转写脚本内完成：句内 ≥1s 静音（RMS < -40 dBFS 振幅实测）一律断条，字幕跟随语音节奏；仍 >12s 的片段按词级时间戳在最大停顿处机械拆完。部分条目因此是句中片段、不以句末标点收尾——实测确认翻译 agent 整文件读入，理解不受断条影响，此为纯观感取舍（用户选定 follow-the-audio）。
- 在线 ASR 存在轻微运行间不确定性（同音频两次提交个别字词不同，实测差异 <0.2% 字符）。
- 本地链（`tools/transcribe_stable.py` + 步骤 2 重组）保留作回退：断网、敏感素材、额度耗尽时使用。
